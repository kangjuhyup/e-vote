# 진행 중 투표 내용 변경 승인 명세

## 목적과 확정된 범위

투표 작성자가 진행 중인 투표의 일부 내용을 바꾸려면 직인이 찍힌 공문 파일과 변경안을 제출한다. 관리자는 공문과 변경 전·후 내용을 확인해 승인하거나 거절한다. 승인 전에는 실제 투표 내용이 바뀌지 않는다.

변경 가능한 항목은 부모 투표의 **제목, 설명(안내문), 종료 시각**, 부모 투표 첨부파일, 기존 후보자의 첨부파일이다. 첨부파일 변경은 추가·교체·제거를 포함한다. 시작 시각, 안건·후보자의 생성/삭제·이름·번호·설명, 선택지, 선거인, 투표 방식/정책, 결제 정보 및 이미 행사된 표는 이 절차로 변경할 수 없다. 투표가 `OPEN`일 때만 요청·승인할 수 있으며 종료·취소된 투표는 재개하지 않는다.

## 현재 동작과 근거

- `VoteAggregate.updateSettings`와 `assertChildResourcesMutable`는 결제에 잠긴 투표 및 초안이 아닌 투표의 일반 수정을 막는다. 이 제한은 유지하고, 승인된 항목에만 별도 명령을 둔다. (`server/src/modules/vote/domain/vote/vote.aggregate.ts`)
- 일반 투표 및 후보 첨부파일 업로드는 작성자 소유권과 초안 변경 가능 여부를 검사한다. 진행 중 변경안의 파일은 승인 전 실제 첨부파일로 연결하면 안 된다. (`server/src/modules/vote/application/command/attachment-target.validator.ts`, `server/src/modules/vote/application/command/attachment-upload.policy.ts`)
- `files`는 메타데이터, 파일 본문은 스토리지에 있다. 기존 `vote_content_change_histories`에는 변경 전·후 스냅샷과 관리자 행위자를 기록할 수 있는 필드가 있으나 현재 워크플로에서 사용하지 않는다. (`server/src/modules/vote/infrastructure/database/entity/attachment.entities.ts`, `server/src/modules/participation/infrastructure/database/entity/result.entities.ts`)
- 관리자 인증은 테넌트의 `vote-admin` 역할을 사용한다. 투표 상세는 진행 중 투표에서 직접 수정 버튼을 비활성화한다. (`server/src/modules/organization/presentation/organization-onboarding/admin-operations.controller.ts`, `ui/src/features/votes/container/vote-detail-container.tsx`)
- 투표 종료는 워커가 종료 시각을 기준으로 처리한다. 승인과 워커의 상태 전이는 같은 투표 행 잠금을 통해 직렬화해야 한다. (`server/src/modules/vote/application/command/handler/process-due-vote-schedules.handler.ts`)

## 사용자 흐름

1. 작성자는 진행 중 투표 상세에서 **내용 변경 요청**을 연다. 현재 값과 승인 가능한 필드만 수정할 수 있다. 필수 변경 사유와 직인이 찍힌 공문 파일을 첨부한다.
2. 공문은 PDF/JPEG/PNG 중 하나, 최대 20MB로 받는다. 시스템은 형식·크기·업로드 완료 여부를 검사하지만 직인 진위는 자동 판정하지 않는다. 요청 화면에 관리자가 직인을 확인한다는 사실을 명시한다.
3. 새 투표·후보자 첨부파일은 변경안 전용 임시 자료로 업로드하고, 기존 첨부파일의 유지·제거 목록과 함께 제출한다. 제출 전후 모두 실제 투표 화면에는 현재 승인된 파일만 보인다.
4. 요청이 제출되면 `PENDING`이 되고 작성자는 상태·변경안·공문을 조회할 수 있다. 한 투표에는 미처리 요청을 하나만 허용한다. 수정이 필요하면 관리자가 거절한 후 새 요청을 제출한다.
5. 같은 테넌트의 `vote-admin`은 관리자 **투표 변경 요청** 화면에서 목록·상세·공문 미리보기/다운로드·변경 전후 비교를 본다. 관리자는 제출된 값을 직접 편집하지 않고 승인 또는 거절한다. 거절 시 사유는 필수다.
6. 승인 시 서버가 투표 상태와 종료 시각을 다시 확인하고, 허용 필드 변경·첨부파일 연결/해제·변경 이력·요청 상태를 한 DB 트랜잭션에서 확정한다. 성공 상태는 `APPROVED`다. 거절은 실제 투표를 건드리지 않고 `REJECTED`와 사유·관리자·시각을 남긴다.
7. 승인 전 투표가 종료/취소되거나 원본이 달라져 더는 적용할 수 없으면 승인을 거부하고 요청을 `INVALIDATED`로 기록한다. 작성자는 결과와 이유를 확인한다. 종료 후 재개·소급 변경은 없다.

## 정책과 동시성

- 종료 시각 변경안은 **승인 시점보다 미래**이고 원래 시작 시각보다 늦어야 한다. 기존 종료 시각이 이미 지난 요청은, 워커가 아직 상태를 바꾸지 않았더라도 승인할 수 없다. 연장과 단축 모두 허용하되 단축으로 이미 지난 시점으로 종료시키지 않는다.
- 일반 수정 API와 기존 첨부파일 API는 진행 중 투표에 계속 409를 반환한다. 변경 요청/승인 전용 경로만 위 항목을 바꿀 수 있다.
- 작성자 제출과 관리자 심사는 서버에서 테넌트·작성자/관리자 권한을 각각 검사한다. 클라이언트의 버튼 숨김은 권한 판단을 대체하지 않는다.
- 승인/거절은 동일 요청에 대해 동시 실행되지 않도록 요청 행과 투표 행을 잠근다. 같은 결정을 재시도하면 확정된 결과를 반환하고, 반대 결정은 409를 반환한다.
- 승인된 모든 필드의 변경 전·후 값, 요청 ID, 사유, 관리자 ID·시각을 감사 이력에 남긴다. 파일은 ID·체크섬·파일명 등의 메타데이터만 이력에 기록한다. 공문과 제안 파일은 승인·거절 후에도 감사 조회에 필요한 비공개 자료로 남기며, 기존 파일 본문을 덮어쓰거나 물리 삭제하지 않는다.
- 후보자 첨부파일은 **기존 후보자 ID**에만 연결한다. 첨부파일 교체는 후보/선택지 ID와 기존 투표 기록을 바꾸지 않는다. 비밀투표의 선거인-선택 연결 정보는 새로 만들지 않는다.
- 공문 및 미승인 자료는 작성자와 해당 테넌트 관리자만 다운로드할 수 있다. 서명 URL과 파일 본문은 감사 로그·API 목록 응답에 넣지 않는다. 스토리지 호출은 DB 트랜잭션 밖에서 처리하고, 승인 시에는 확인된 파일 메타데이터만 사용한다.

## 계약과 화면

- 별도 변경 요청 리소스에 투표 ID, 작성자, 테넌트, 제출 시각, 상태, 사유, 공문 파일 ID, 변경 전 스냅샷, 제안 값/첨부파일 ID, 심사자·심사 시각·거절/무효화 사유를 저장한다. 미처리 요청은 투표당 하나만 허용하는 DB 제약을 둔다.
- 작성자 API: 변경안용 파일 업로드 준비/확인, 요청 제출, 내 투표 요청 목록/상세 조회. 관리자 API: 같은 테넌트의 요청 목록/상세, 승인, 거절. 파일 다운로드는 소유권·관리자 권한을 확인하는 별도 경로로 발급한다. 쓰기 응답은 요청 ID·상태 중심으로 작게 유지한다.
- 투표 상세에는 `OPEN`일 때만 **내용 변경 요청** 진입점과 최신 요청 상태를 표시한다. 요청 화면은 변경 전후 비교, 공문 업로드 필수 표시, 미제출/제출 중/오류/완료 상태를 제공한다. 관리자는 목록에서 `PENDING` 필터와 상세 비교·공문 확인·승인/거절 조작을 이용한다.
- 투표 및 후보자 자료의 일반 조회는 승인된 자료만 보여준다. 승인 후 관련 투표·관리자 요청 캐시를 무효화해 최신 종료 시각·내용을 표시한다. 공문 업로드, 승인, 거절은 화면에서 결과를 명확히 알리고 키보드로 조작할 수 있어야 한다.
- 자동 문자 발송, 외부 공문 발송, 직인 OCR/전자서명 검증, 후보·선택지 변경, 투표 재개는 이번 범위에 포함하지 않는다.

## 구현 순서와 검증

1. **backend**: 요청 상태/필드 허용 정책, 권한, 행 잠금 및 감사 불변식을 도메인·애플리케이션에 정의한다. 공문·제안 파일을 기존 스토리지 계약과 분리해 승인 전 노출을 차단한다.
2. **backend**: 요청/파일 참조 스키마와 마이그레이션, 제출·조회·승인·거절 API를 구현한다. 승인 시 현재 투표/요청 재검증과 원자적 적용, 워커 종료와의 경합을 처리한다.
3. **frontend**: 작성자 요청 화면과 상태 표시, 관리자 검토 화면 및 접근/오류/빈 상태를 연결한다.
4. **qa**: 도메인·핸들러·저장소·HTTP 권한 테스트, 업로드 실패/중복 심사/종료 직전 경합 테스트, UI 흐름 테스트, 서버·UI 린트와 빌드를 실행한다.

완료 판정은 다음과 같다.

- 공문 파일 업로드가 완료되지 않은 요청은 제출되지 않고, 제출만으로 투표 내용이 바뀌지 않는다. 관리자는 승인 전 파일을 열어 직인을 확인할 수 있다.
- 관리자가 승인하면 지정한 필드와 파일만 한 번 적용되고, 변경 전후·심사자·공문이 감사 가능하다.
- 거절·무효화된 요청은 실제 투표를 바꾸지 않으며 작성자가 사유를 볼 수 있다.
- 다른 작성자/테넌트 사용자와 비관리자는 공문 열람·제출·심사를 할 수 없다.
- 투표가 종료되었거나 승인 시각에 이미 종료 시각을 지난 경우에는 승인·재개가 불가능하다.
- 기존 참여 기록, 후보/선택지 ID, 정책, 결과 집계는 변경 전후 동일하다.
